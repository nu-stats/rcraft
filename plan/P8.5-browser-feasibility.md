# P8.5: can RCraft run in a browser? (feasibility study, 2026-11-17)

**Answer: yes, as a reduced edition, for about two weeks of work.** R runs in the browser through
webR (R compiled to WebAssembly, run in a Web Worker). RCraft's dialogs, code generator, Stata
translator and data readers already build for the browser. What has to be written new is the
layer that talks to R, the file handling, and the parts of the window that call the operating
system. Recommended: build it after the installers (P8.2), and only if a no-install edition is
wanted, for example for teaching in a browser.

## What was checked, and how

| Question | Finding | How it was checked |
|---|---|---|
| Does R run in a browser? | Yes: webR 0.6.1 (released 2026-11-10) runs R 4.6.0 on `wasm32-unknown-emscripten`, a 32-bit platform. | Ran R in webR's own page: `R.version.string`, `.Machine$sizeof.pointer`. |
| Same numbers as desktop R? | Yes, on the checks run: `lm(mpg ~ wt)`, `fixest::feols(mpg ~ wt \| cyl)` and sandwich's HC1 standard errors print the same digits as R 4.4.3 here. | The same lines in webR and in the pinned desktop R. |
| Plots as PNG files? | Yes: `capabilities("cairo")` is TRUE and `png()` writes a real file; JavaScript reads it with `webR.FS.readFile`. | `png()` in webR; webR's plotting and communication docs. |
| Packages? | 24,640 packages for R 4.6 at repo.r-wasm.org, compiled code included. Every package RCraft uses is there (sandwich, lmtest, MASS, nnet, survival, lme4, fixest, plm, survey, sampleSelection, marginaleffects, car, ggplot2, dplyr, data.table, haven, readxl, openxlsx2, gt, flextable, officer, modelsummary, knitr, rmarkdown) **except arrow**, so Parquet and Feather would not be offered. sandwich and fixest installed in 3 seconds. | The repository's `PACKAGES` index for 4.6; `webr::install()` in webR. |
| Which RCraft crates build for the browser? | `core`, `rproto`, `rdata`, `rpkg`, `rcodegen`, `catalog`, `statatr`, `rgraph`, `report` and `rhost` pass `cargo check --target wasm32-unknown-unknown`. `rpkg` needed one change, made here: its network fetcher (ureq with rustls, whose `ring` does not build for wasm) is now left out of browser builds. `engine` and `ui-egui` do not build yet (below). | `cargo check` for each crate. |
| How big is the download? | The R binary (`R.wasm`) alone is about 12 MB, before base R's packages and RCraft's own program. | The file's size on webR's server. |

## The licence question

webR's own code (its scripts, loader and REPL) is MIT. The **webR binaries contain R and are
GPL-3**. RCraft would stay on the right side of AGENTS.md §1 the same way it does now:

- R runs in its own Web Worker, and RCraft talks to it only by messages: code written to R's
  console, output read back, files through webR's file system. That is the browser's equivalent
  of the pipes RCraft uses today. RCraft's program is never linked with R's.
- RCraft should use webR's **console channel only** (`writeConsole`, and reading the `stdout` and
  `stderr` messages), which carries RCraft's existing text protocol (`rproto`) unchanged, not
  webR's in-page R object proxies.
- webR is loaded either from webR's own servers (RCraft then distributes none of it) or from
  RCraft's site, shipped alongside RCraft with webR's licence text and source offer, as AGENTS.md
  already allows for an R bundled in installers.
- New hosts for `docs/network.md`, in their own commit, when the build exists: webR's servers for
  R itself, repo.r-wasm.org for packages. Installing stays on the user's yes.

## What has to be built

| Part | What it is | Estimate |
|---|---|---|
| A web session for `engine` | The same calls as `rhost::Session` (start, run, next event, interrupt, restart) backed by webR's console through `wasm-bindgen`. Today's session uses threads and `Instant`, which the browser does not have; timing moves to a browser clock and events are read once per frame. | 2 to 3 days |
| `bootstrap.R` in webR | Tables and plots are already passed as files; they would be read from webR's file system instead of a temporary folder. Interrupting R needs the page served cross-origin isolated (below). | 1 day |
| The window for the browser | eframe's web runner; the native-only pieces (`rfd` file dialogs, `arboard` picture copy, `winit` and `softbuffer` options) left out. The biggest change: 19 file dialogs are called in a blocking way, and in a browser a file is picked with an upload and saved as a download, both asynchronous. | 3 to 5 days |
| Storage | About 120 `std::fs` calls (settings, recent lists, scripts, projects). In a browser: the browser's own storage for settings, uploads and downloads for files, a project saved as one .zip download. | 1 to 2 days |
| Packages window | List and install from repo.r-wasm.org instead of CRAN, through webR's installer. | 1 to 2 days |
| Hosting and CI | A build step, a size budget, a static site with the two headers below. | 1 day |

**About two weeks in all.** Each part can be checked against the desktop build, since the R code
RCraft writes is the same.

## What the browser edition could not do

- **Memory:** webR is 32-bit, so R has at most 4 GB, and browsers often give less (phones far
  less). Large data sets belong in the desktop app.
- **Files:** no folders on the user's disk. Data comes in by upload, and results, scripts and
  projects go out as downloads. No Quarto rendering (Quarto is a program on the computer).
- **Formats:** no Parquet or Feather (no arrow).
- **Interrupting R** works only when the page is served with `Cross-Origin-Opener-Policy:
  same-origin` and `Cross-Origin-Embedder-Policy: require-corp`. GitHub Pages cannot send those,
  so it would need a host that can.
- **The network from R:** `download.file()` works only from servers that allow it (CORS).
- **Picture copy:** a plot is saved as a download instead of copied as a picture.

Stata mode, the dialogs, the translator, the help that comes from R, the report (Word and web
pages, through officer and gt) and the Model table would all work, as they are R code.

## Recommendation

1. Do P8.2 (installers) first: that is how most people will get RCraft.
2. Keep the browser door open: the shared crates build for wasm now. A CI check that they keep
   building (`cargo check --target wasm32-unknown-unknown` for those crates) would stop that
   breaking unnoticed; it needs the wasm target added to CI.
3. Build the browser edition when a no-install version is wanted, in the order of the table above.
   The web session comes first, since everything else can be tried once R answers.

Sources: webR's documentation (docs.r-wasm.org: communication, plotting, packages, serving,
networking), its licence file and release notes on GitHub, and the package index at repo.r-wasm.org;
the checks above were run in webR's own page and in the R 4.4.3 that RCraft's CI pins.
