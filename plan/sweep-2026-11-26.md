# App sweep, 2026-11-26

What breaks in the app as the user runs it (Pinokio, `target/release/rcraft-desktop`,
the user's own R 4.6.2 with its 170 packages), though CI passes.

How: a temporary harness (`crates/ui-egui/src/app/sweep.rs`, not committed) drives the
real `App` through the same actions the window uses. It ran every catalog dialog (136)
with its choices filled in on a made-up data frame, and 75 common Stata lines three ways:
no data, data opened with File > Use my file, and data opened with `use`.

## Why CI did not catch these

- CI runs R 4.4.3 with every package installed; the app finds R 4.6.2 on PATH, which
  lacks 8 of the packages dialogs need.
- Stata-mode tests always load data with `use` first, so the menu path is never run.
- Tests that cannot find R or a package print "skipped" and pass.

## Broken

| # | Where | What happens | Severity |
|---|---|---|---|
| 1 | Stata mode after File > Use my file (or R code, or the Data window) | The translator only knows data loaded by a Stata line. Every command prints nothing or says "no data is in memory"; `describe` reports 0 observations and 0 variables while the data is on screen. | critical |
| 2 | Command box | A one-line field. The panel can be dragged taller, but the box stays one line; only blank space grows. | high |
| 3 | Stata mode: `summary`, `sysuse`, `webuse`, `help summarize` | Nothing happens, apart from a "not translated" comment in the echoed code. `summary` should say it is not a Stata command and suggest `summarize`; `help summarize` should open Help. | medium |
| 4 | Stata mode: a failed estimation (`regress y nosuchvar`) | Wipes the earlier model, so a following `predict` fails with "object 'stata_estimates' not found". Stata keeps the earlier results. | medium |
| 5 | 21 dialogs (fixed effects, panel, survey, IV, Heckman, SEM, meta-analysis, VAR, Bayesian) | Need fixest, plm, survey, lavaan, metafor, vars, rstanarm, sampleSelection, which the user's R does not have. The dialog offers an install; that install flow was not checked here. | medium (check) |
| 6 | Stata mode: a variable that is missing, or of the wrong type | Raw R/dplyr errors ("object 'nosuchvar' not found", "Can't combine `x` <character>…") instead of Stata's "variable not found" / "type mismatch". `tab` on a missing variable prints an empty table with a warning instead of failing. | low |
| 7 | Stata mode: `list` | Every `list` prints the warning "Unknown or uninitialised column: `stata_sep_`". | low |
| 8 | Objects > Model > Fit statistics, Average marginal effects | On an object that is not a model, raw R errors ("no 'nobs' method", a long list of classes) instead of the clear "this works for …" the other Model dialogs give. | low |

The other dialog errors in the sweep came from the harness choosing unsuitable
variables (a 3-level factor for a t-test, say); those dialogs answered with clear messages.

## Not covered by this sweep

Clicks and layout (pane resizing, dialogs as drawn, menus), the do-file window, the
Packages window, the Graph window, the data editor, sessions and projects. Those need a
hands-on or picture-based pass.
